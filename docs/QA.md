# وضعیت بررسی نسخه ۰.۲

تاریخ: ۲۰۲۶/۱۱/۱۳

شش تست موتور موفق بود. همه ۲۴ ترکیب انتخاب با ذخیره و بازیابی هر صحنه به دو پایان معتبر رسیدند. تست جدید، ذخیره شماره قاب کمیک، برگشت به قاب قبل، جلوگیری از عبور با دستور گفت‌وگو و رد ذخیره نامعتبر کمیک را بررسی می‌کند.

npm run check و npm run build موفق بودند. چهار تصویر داخل خروجی مستقل HTML جاسازی شده‌اند؛ خروجی به پوشه assets یا شبکه احتیاج ندارد.

در مرورگر، شروع مأموریت، تصویر محمد، تصویر مهندس با نشان روی سینه، ورود به کمیک، حرکت بین قاب‌ها، بازکردن صفحه کامل و رسیدن از آخرین قاب به میز مدارک بررسی شد. در میز مدارک، دکمه ادامه پیش از خواندن مدارک غیرفعال بود. تازه‌سازی صفحه و ادامه بازی، قاب سوم کمیک را بازیابی کرد.

تصاویر محمد و مهندس و صفحه کامل کمیک در نمای دسکتاپ دیده و بررسی شدند. پس‌زمینه کارگاه بدون شخصیت جایگزین شد تا شخصیت‌های پیش‌زمینه با تصویر پس‌زمینه تکرار نشوند. در اندازه موبایل، نمایش قاب جدا فعال شد و عرض محتوای سند با عرض نمای قابل استفاده برابر بود؛ سرریز افقی نداشت. ثبت اسکرین‌شات در اندازه موبایل با خطای ابزار روبه‌رو شد؛ بنابراین کنترل موبایل بر پایه وضعیت رابط و اندازه عناصر است، نه تصویر ثبت‌شده.

خروجی مستقل sangarsazan.html نیز جداگانه در مرورگر باز شد. تصویر محیط و شخصیت از data:image بارگذاری شدند و کنسول خطایی نداشت. بسته اندروید و صوت در این نوبت تست نشده‌اند.

نسخه ۰.۱ نیز پنج تست موتور موفق داشت، اما در آن نوبت اتصال پیش‌نمایش محلی برقرار نشد. محدودیت پیش‌نمایش دسکتاپ در نسخه فعلی برطرف شد.

## نسخه ۰.۳ · چندفصلی و تصویرسازی تازه

تاریخ: ۲۰۲۶/۱۱/۱۳

هفت تست موتور موفق شدند؛ شامل پیوند صحنه‌ها، شرط مدارک، همه ۲۴ ترکیب تصمیم تا پایان، ذخیره و بارگذاری، ذخیره قاب کمیک و رد داده نامعتبر. راهنمای پیمایش تست با مسیر معرفی محمد و انتخاب آغازین تازه هماهنگ شد. `npm run check` و `npm run build` موفق شدند و `release/sangarsazan.html` دوباره ساخته شد.

فهرست فصل‌ها اکنون از `CHAPTERS` خوانده می‌شود، شناسه عملیات در موتور و رابط استفاده می‌شود و ذخیره‌های خودکار برای هر شناسه جدا هستند. فصل جدید باید به آرایه `CHAPTERS` افزوده شود؛ همه فصل‌ها هنگام آغاز برنامه اعتبارسنجی می‌شوند. خیبر همچنان تنها عملیات محتوایی این نسخه است.

شش قاب تصویرسازی تازه به صحنه‌های خیبر وصل شدند. تصاویر قبلی و صفحه کمیک قبلی حفظ شدند. هر تصویر جدید به صورت WebP در `dist/assets` و در خروجی تک‌فایلی جاسازی شده است.

تست تعاملی مرورگر کامل نشد: مرورگر ابری به سرور محلی دسترسی نداشت و Chromium خط فرمان در این محیط به خاطر محدودیت socket/ptrace اجرا نشد. بنابراین نتیجه آزمون مرورگر یا موبایل ادعا نمی‌شود. فایل مستقل از نظر ساخت موفق است و مسیرهای موتور با تست خودکار بررسی شده‌اند.


## نسخه ۰.۴ · هسته و انتخاب عملیات

صفحه هسته و فهرست عملیات از هم جدا شدند؛ ورود به خیبر از کارت تصویری آن انجام می‌شود. دکمه بازگشت به هسته در نوار بالایی اضافه شد. پس‌زمینه هور روز و تصویر یونس به فایل مستقل HTML پیوست شدند. در اجرای CI با شناسه 43482233303، `npm run check`، `npm test` و `npm run build` همگی موفق شدند و فایل HTML تک‌فایلی ساخته شد. آزمون بصری مرورگر انجام نشده است.


## نسخه ۰.۵ · میز مأموریت، نقشه و ناوبری

نقشهٔ بازسازی‌شدهٔ عملیات خیبر در میز مدارک و پنجرهٔ نقشه نمایش داده می‌شود و ارجاع/مجوز CC BY 3.0 دارد. دکمهٔ برگشت از میز مدارک دیگر غیرفعال نمی‌ماند و مدرک‌های بازنشده را اعلام می‌کند. دکمهٔ «از اول» با تأیید، روایت را از معرفی محمد آغاز می‌کند. متن مبنای اولیه در پنجرهٔ درباره به تحقیقات استودیو بیدرانو تغییر کرد. خانواده فونت Yekan به عنوان فونت اصلی تنظیم شد.

در CI برای commit `ed382cc`، workflow «Verify game core» با موفقیت پایان یافت و خروجی مستقل HTML در artifact با نام `sangarsazan-browser-core` ساخته شد. آزمون بصری دستی دسکتاپ و موبایل در این محیط انجام نشده است. بارگیری نقشه و فونت از منبع بیرونی به اتصال اینترنت وابسته است؛ برای نقشه، توضیح متنی و پیوند منبع در حالت عدم دسترسی به تصویر نمایش داده می‌شود.

کارت‌های میز مدارک با دو عکس آرشیوی واقعی و نقشهٔ بازسازی‌شده تکمیل شدند؛ منابع و مجوزها در `docs/ART_SOURCES.md` ثبت شده‌اند. برای commit `cdd99d2` اجرای «Verify game core» با موفقیت پایان یافت و HTML مستقل ساخته شد. بررسی بصری دستی انجام نشده است.


## نقشه فارسی، عکس عملیات و ژست محمد

نقشه اصلی پنجره به شماتیک فارسی با اندازه محدود تبدیل شد؛ نقشه انگلیسی مرجع در بخش بازشونده و اندازه کوچک‌تر باقی مانده است. عکس ارسالی متین در کارت عملیات هسته استفاده می‌شود و عکس پل خیبر روی کارت برچسب کارگاه قرار دارد. ژست تازه محمد با وصله جهاد سازندگی روی جیب سینه در گفت‌وگوی معرفی استفاده می‌شود. اطلاعات شروع، رمز، سازمان محورها و نتیجه الحاق در طلائیه بر پایه مقاله همشهری‌آنلاین بازنویسی شده است.

برای commit `47e1be1` اجرای «Verify game core» موفق شد و HTML مستقل ساخته شد: https://github.com/matin1151/sangarsazan/actions/runs/45136381238. بررسی بصری دستی دسکتاپ و موبایل انجام نشده است. عکس‌های آرشیوی و فونت از منابع اینترنتی بارگیری می‌شوند.

## فصل دوم شناسایی و فصل سوم ساخت نمونه، ۲۰۲۶/۱۱/۲۳

در محیط توسعه، ۱۷ آزمون Node موفق شدند: هفت آزمون هسته قبلی (از جمله ۲۴ مسیر روایت)، هفت آزمون کارگاه و سه آزمون شناسایی. تطابق کلمه‌به‌کلمه دیالوگ‌های شناسایی با راهنمای ثبت‌شده، پاسخ غلط و تلاش دوباره، قفل مراحل، ثبت دفترچه، ذخیره/بازیابی، سطحه معیوب، زاویه اشتباه، هم‌راستایی گوشواره، پین کوتاه، مهار نامناسب، شکست آزمایش و اصلاح بدون شروع مجدد پوشش داده شدند. npm run check و npm run build موفق شدند.

اجرای Chromium در محیط توسعه به علت محدودیت socket/ptrace متوقف شد. مرورگر ابری نیز به localhost دسترسی نداشت. این‌ها آزمون موفق بصری محسوب نمی‌شوند. workflow جداگانه برای آزمون مرورگر واقعی در GitHub Actions اضافه شده؛ نتیجه نهایی آن پس از اجرا در ادامه این سند ثبت خواهد شد. آزمون لمس در آن شبیه‌سازی Pointer/Touch در Chromium است؛ آزمون روی گوشی فیزیکی یا APK نیست.

### اجرای موفق مرورگر

اجرای GitHub Actions شماره 45238107491 روی commit 889ee955 موفق شد. خروجی ثبت‌شده: `PASS full UI mouse 1366x768`، `PASS full UI touch 844x390` و `PASS offline HTML and no page errors`.

در هر دو اندازه، مسیر کامل ساخت با کشیدن سطحه، چرخش، تعویض قطعه معیوب، جابه‌جایی خارج مسیر و بازگرداندن، نمای نزدیک اتصال، شکست نصب پیش از هم‌راستایی، کشیدن پین و زنجیر، مهارها، آزمایش ناموفق، اصلاح اتصال و کشش و آزمایش موفق اجرا شد. خروج از کارگاه و ادامه، سپس مسیر کامل شناسایی با پاسخ‌های نادرست، اندازه‌گیری سه نقطه، دفترچه، تازه‌سازی مرورگر و بازیابی، هر سه آزمایش و پایان مأموریت نیز اجرا شد. اندازه سند از viewport بزرگ‌تر نبود و دکمه اصلی داخل قاب ماند.

اولین دو اجرای مرورگر به‌علت انتخابگرهای اسکریپت آزمون متوقف شدند. اجرای سوم، مشکل واقعی رویداد لمس هنگام بازسازی پنجره اتصال را آشکار کرد؛ مدیریت pointer و پاک‌کردن محتوای پنجره بسته‌شده اصلاح شد و اجرای چهارم موفق بود. تصاویر دسکتاپ و موبایل در artifact با نام chapters-browser-evidence همان اجرا موجودند. این نتیجه آزمون گوشی فیزیکی، Safari یا Android APK محسوب نمی‌شود.

نسخه بافت‌دار در اجرای 45238958002 روی commit 5e551e05 نیز همه سناریوها را گذراند. بررسی دستی اسکرین‌شات‌ها یک ایراد چیدمان دسکتاپ را نشان داد: با شناورشدن قاب شخصیت‌ها، بوم در ردیف کوتاه بالایی افتاده بود. ردیف بوم اصلاح و کنترل حداقل ارتفاع قابل استفاده به آزمون مرورگر اضافه شد. این نمونه نشان می‌دهد عبور از آزمون تعامل به‌تنهایی تضمین کیفیت بصری نیست.
